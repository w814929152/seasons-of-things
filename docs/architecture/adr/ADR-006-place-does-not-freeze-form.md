# ADR-006 · 放置（Place）只写 pos，不冻结 form

- 状态：**已接受（有争议，需主理人确认）**
- 日期：Phase 4
- 决策者：程基岩（engineering-lead-impl）
- 相关：GDD §4.3 C3、design/level/level_01_design.md §5.2 / §9.1 / §11 验收 8

---

## 上下文

两份权威文档对「把背包里的东西放回世界」给出了**互斥**的规格：

- **GDD §4.3 C3**：> 放回世界：玩家把背包中的实体放到 `L` → 追加 C1（`pos=L`）+ C3（`form=` 携带形态）。因此「把崭新钥匙带回锈时」= 在 T2 放下一个 `form=KEY_NEW` 的钥匙。
- **关卡文档 §5.2 硬规则提醒 / §9.1 死局核查 / §11 验收 8**：> T2 砝码虽是 `WEIGHT_SEIZED`（锈死），只要它在 (6,3) 上，压力板照样被压住 —— 这是**正确行为**。> 砝码已放上压力板 → T2 形态 `IMMOVABLE` 取不回 → 切到 T1 可取（T1 形态仍 OK）。

若按 GDD C3 冻结形态，则标准解法把砝码放上板后，T2 的砝码形态会变成 `WEIGHT_OK`（冻结），**验收 8 的用例前提（T2 形态为 `IMMOVABLE`）根本无法构造**，且 §9.1 的自救路径描述失效。

## 备选方案

| 方案 | 后果 |
|---|---|
| **A. 冻结形态（严格遵循 GDD C3）** | 关卡文档 §9.1 与 §11 验收 8 失真；「砝码锈死在板上」这条最有味道的叙事消失；但「把新钥匙带回锈时」可显式演示 |
| **B. 只写 pos（本决定）** | 物件放回世界后继续走自己的时间线；关卡文档全部用例成立；冻结完全由背包承担 |
| C. 双语义：放到"容器"不冻结、放到"地面"冻结 | 语义复杂、玩家不可预测，违反 P3 与"玩家能口头复述规则" |

## 决定

**采用 B：`place()` 只写 `pos`（+ 必要时清 `removed`），不写 `form`。**

理由：
1. A5「状态冻结 / 携带」的**核心体验**是「**手上的**不变」—— 它已经由 `InventoryItem` 完整承担（拾取瞬间冻结 `form`+`tags`，切时刻不变，测试已覆盖）。放置路径是否冻结，对 A5 的教学目标**没有贡献**。
2. B 让关卡文档 §5.2 / §9.1 / §11-8 三处描述**同时成立**，这是本次交付必须逐条通过的验收。
3. B 的规则更可复述：「东西回到世界上，就重新跟着世界变」—— 符合玩家心智模型第 1 句「世界上的东西会随时间变，我手上的东西不会」。

**例外**：`use()` 于锁具开锁时，钥匙"留在锁孔"，此时写入 `pos`（门格）+ `form`（携带形态）。理由：那把钥匙就是玩家手上那把，若不写 form，会出现"断钥匙卡在锁孔里"的怪异画面（关卡文档 §7 实现注记希望的表现是"那把断掉的钥匙如今不曾存在过"）。

## 后果

**正面**：关卡文档验收 8 可由标准解法直接构造（T2 砝码 = `WEIGHT_SEIZED` + `IMMOVABLE` + `PRESSER`，压力板仍 pressed，闸门仍开）—— 实测通过。

**负面**：
- 与 GDD §4.3 C3 文字不一致 → **已在 architecture §12.3-D2 披露，需主理人裁决**。
- 后续若出现"必须把过去的完好形态放到未来某处"的谜题（A5 的放置变体），需要显式启用携带语义；`place()` 已按开关化组织，改动集中在 `TimeController.place()` 一处。

## 测试证据

- `tests/test_level_01_solvable.gd`：步 8 → `resolve(WEIGHT,2).pos == (6,3)` 且 `form == WEIGHT_SEIZED` 且 `tags ∋ IMMOVABLE` → `plate_pressed(2) == true` → `grate_open(2) == true`。
- `tests/test_immovable_pressure.gd`：5 条专项断言（IMMOVABLE / OCCLUDED / HOT 三种形态锁下压感均保持）。
