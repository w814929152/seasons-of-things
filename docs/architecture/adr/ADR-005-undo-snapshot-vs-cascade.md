# ADR-005 · 撤销机制：整步快照回滚（取代 parent_seq 级联删除）

- 状态：**已接受**（Phase 4 实现）
- 日期：2026-xx-xx（Phase 4）
- 决策者：程基岩（engineering-lead-impl）
- 相关：GDD §7.2、architecture §7、ADR-001

---

## 上下文

GDD §7.2 与架构 §7 都规定：

> 单步撤销 = 弹出 `overrides` 中 `seq` 最大的一条，并**按 `parent_seq` 级联删除其派生的 forward 传播记录**。

而验收标准第 7 条要求：

> 撤销 10 次后状态与初始态**逐字段一致**；时砂无负数。

问题在于：一次"玩家操作"会同时改动**五类状态**——
1. `overrides`（父记录 + N 条 forward 派生）
2. `current_t`（切换时刻本身也是一步操作）
3. `hourglass`（时砂消耗 / 撤销需全额返还）
4. `inventory`（拾取/消耗/放置都动背包）
5. `player_pos`（移动也是一步操作）

`parent_seq` 级联删除**只能覆盖第 1 类**。要覆盖 2–5 类，必须另外再维护一套平行的历史结构 —— 两套机制并存、且要保证它们同步，是漂移 bug 的温床。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. `parent_seq` 级联删除**（GDD 原方案） | 内存省；语义"精确" | 只还原 Override；时刻/时砂/背包/坐标需另建历史；两套栈易漂移；验收 7 的"逐字段一致"要同时对齐两套栈 |
| **B. 整步快照回滚**（本决定） | 一处实现覆盖全部 5 类状态；撤销语义 = "回到这一步之前"，天然满足逐字段一致；无漂移面 | 每步存一份 `overrides` 深拷贝；本关规模（≤ 数十步 × 数十条）内存可忽略 |
| C. 反向操作（command pattern + undo()） | 内存最省 | 每个动词都要写一份正确的逆操作，`resolve`/派生/时砂三者交错时极易漏；本作有 forward 传播，逆操作正确性难证 |

## 决定

**采用 B：每步操作前压一整份状态快照，撤销 = 弹栈还原。**

- `TimeController._push_history()` 在任何一次**会改变游戏状态**的操作（shift / take / place / use / walk_to）**之前**调用。
- **逐格推进的移动（第八轮）另走一路**：`mark_move_start()` 显式入栈**一次**，之后每次
  `commit_cell()` 落点都**不**再压栈 —— 于是整段连续移动（长按方向键 / 拖动鼠标 /
  一次点击的多格寻路）在撤销栈里只占 **1 条**记录，按一次 `Z` 整段回滚。
- 快照内容：`current_t`、`hourglass`、`player_pos`、`won`、`overrides`（深拷贝）、`inventory`（深拷贝）、`seq`。
- `undo_step()` = 弹栈顶 + `_restore_state()` + 重发信号。
- `reset()` = 压栈（让重置本身也可撤销）+ 还原 `setup()` 时保存的 `_initial_snapshot`。
- **`Override.parent_seq` 字段保留**：forward 派生记录仍标记父记录，供调试视图与时间轴 UI 追溯因果链，但**不作为撤销的实现依据**。

## 后果

**正面**
- 验收 7（撤销后逐字段一致、时砂全额返还、无负数）由一条 `TimeController.state_diff()` 直接证明，实测通过。
- 撤销永远免费、不限次数 → 满足设计支柱 P3「永不惩罚」与关卡文档 §9.1「时砂耗尽 → 撤销自救」。
- 新增动词时无需再写逆操作。

**负面 / 代价**
- 内存：每步一份 `overrides` 深拷贝。规模估算：本关一次操作最多产生 4 条 Override（1 父 + 3 派生），10 步 ≈ 40 条小对象，可忽略。若后续关卡做到数百步，可改为「只存 delta」或「只在关键节点存快照 + 中间重放」。
- 与 GDD §7.2 文字表述不一致 → **已在 architecture §12.3-D3 显式披露，需主理人裁决确认**。若主理人坚持 GDD 原文，需要接受"验收 7 只能靠两套栈协同实现"的额外复杂度。

## 测试证据

- `tests/test_undo_restore.gd`：10 次操作 → 10 次撤销 → `state_diff` 为空；时砂回到 12；坐标回到操作前；栈见底后 `undo_step()` 返回 false 不报错；`reset()` 回到出厂态；时砂耗尽后仍可撤销并返还。
