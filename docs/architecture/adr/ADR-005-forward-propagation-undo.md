# ADR-005：正向传播、撤销级联、背包"时间之外"、时砂派生量与残影真值源

- **状态**：已采纳（对齐 GDD §4.2、§4.3、§7.2、§5 L2、§5.1、§2.5）
- **决策者**：engineering-lead
- **关联**：architecture.md §3.3b / §3.7 / §7 / §4

## 上下文
三个强耦合的机制细节，若实现错一处，关卡 1 直接不可解或出现祖父悖论。必须单列 ADR 固化语义，并在代码注释中复述（design-strategist 已预警）。

## 决策

### 1. 传播只向未来（祖父悖论唯一防线）
| 方向 | 规则 |
|---|---|
| 向未来（t 增大） | ✅ 传播。玩家写入默认 `propagate = "forward"` |
| 向过去（t 减小） | ❌ **绝不传播**，写进代码断言（`resolve_state` 中 `if o.t_index > t: continue`） |
| 同时刻 | ✅ 立即生效 |

- **级联三规则（穷尽）**：C1 位移（`pos` forward）/ C2 取离世界（`pos=POS_VOID` forward，背包冻结拾取瞬间 form）/ C3 形态转换（`form` forward）。
- **放回世界** = C1（`pos=L`）+ C3（`form=` 携带形态）。

### 2. 撤销按 parent_seq 级联删除
- forward 传播的记录必须带 `parent_seq`（指向派生它的那条 Override 的 `seq`）。
- 撤销父记录时，**级联删除其所有 forward 派生子记录**，否则未来态残留、状态错乱。
- 撤销**零代价、不限次数**；时砂是派生量，撤销弹 action_log 记录后**自动**回来（无"退还"动作）；撤销/重置永远免费可用（支柱 P3 永不惩罚）。

### 3. 背包是"时间之外"的存储
- 持有 = `{entity_id, form}`，**切时刻不变**（手持冻结，GDD §2.1、§5 L2）。
- 背包内容**不参与 resolve**（不进 Override 层），是玩家随身携带的"时间外"物品。
- 容量上限 2（level_01）；超限拒绝持取并提示。

### 4. 必须写进代码注释的例子（防误解，GDD §4.4）
> 玩家在 **T1** 取走钥匙 → T2、T3 钥匙 `pos=POS_VOID`（缺席），但 **T1 本身仍显示钥匙**（写入点自身生效），**T0 不受影响**。
> 玩家随后在 **T3** 放下这把钥匙 → T3 出现钥匙，**T2 仍然空着**。
> **这不是 bug**：你从 T1 抽走了它，历史里 T2 就没有钥匙；T3 放下的是新插入的物品。UI 提示「它将从此时开始存在」。
>
> 另一例（level §7 步骤 4 注记）：T1 取走钥匙的 `pos=VOID @T1 forward` 会以更晚 `seq` 覆盖步骤 2 留在 T2 (3,1) 的断钥匙残骸——「你回到过去把它拿走了，那把断掉的版本就不曾存在」。UI 提示「那把断掉的钥匙，如今不曾存在过」。

### 5. 时砂是派生量，不是计数器（GDD §5.1，硬规则）
```gdscript
func sand_remaining() -> int:
    var spent := 0
    for a in action_log:                 # 未被撤销的操作序列
        if a.type == &"SHIFT":
            spent += abs(a.from_t - a.to_t)
    return level.sand_capacity - spent
```
- **不存可变计数器**，无 `spend_sand`/`refund_sand`。撤销 = 从 `action_log` 弹记录 → 时砂自动回来（切换消耗与操作消耗同源同算，无"分开结算"，无两套账本）。
- **时砂永不负数**：`spent > cap` 时 SHIFT 在输入层被拒，超限构造上不可能，无需 clamp。
- **撤销/重置永远免费可用**（防软锁死底线）：时砂耗尽只拒新切换，绝不阻止撤销/重置。
- **设计依据**：P3 永不惩罚。时砂约束的是"最终留下的解法路径效率"（配最少切换评星），非给探索收税。

### 6. 残影唯一真值源 = resolve_state 含 Override（GDD §2.5）
- 残影是渲染层"同屏渲染多时刻"，真值来源**必须**与玩法层同一个 `resolve_state(e,t)`（含 Override 后状态）。**禁止**开第二套"原始 chain"真值源。
- 理由：一致性（两套真值源必出"残影在 A、实体在 B"事故）+ P2 残影可信 + G3 顿悟主反馈（搬砝码后残影显示 T2/T3 都到压力板上）。
- 防剧透靠**时刻锁 L5**（残影永不显示未解锁时刻），非靠隐藏 Override。
- 渲染层功能，逻辑层不感知；仅 Override 写入/切时刻时置脏重算，不每帧 resolve。

## 后果
- **正向**：语义明确、可断言（§9 验收 2/3/4 直接覆盖）；关卡 1 可解性有保障；时砂派生化消除两套账本对账风险。
- **负向**：`parent_seq` 级联增加撤销实现复杂度；背包冻结需在切时刻时特殊处理（不 resolve）。
- **风险**：这是最容易被"修 bug 修坏"的地方——任何对"取走→放下"时序的"修正"都可能破坏可解性。已在 tech_checklist 列为高风险项，改动须同步 design-strategist。
