> 引擎：Godot 4 ｜ 配套文档：`design/concept/concept_doc.md`、`design/level/level_01_design.md`
> 强度：lean ｜ 本文所有数据结构均可被程序直接照抄

## 1. 机制概述与玩家心智模型

### 1.1 一句话
玩家在一个房间的 **N 个离散时刻**之间切换当前时刻；同一个「实体」在不同时刻拥有不同的**形态 / 位置 / 可用性**。玩家通过在正确的时刻做正确的动作来解谜。

### 1.2 玩家心智模型（三句话，必须能被玩家口头复述）
1. **世界上的东西会随时间变，我手上的东西不会。**
2. **我动过的东西，会影响它以后的样子，不会影响它以前的样子。**
3. **有些事只能在特定的那一刻做**（太烫 / 锈死了 / 长太粗了）。

> 这三句话就是全部规则的教学目标；任何新机制若不能装进这三句话，就是范围膨胀。

### 1.3 核心循环
```
观察（残影对比全部时刻） → 判断「我要的形态在哪一刻」
  → 切换时刻 → 持取/使用 → 切回目标时刻 → 使用 → 门开
```

### 1.4 明确不做（防止范围漂移）
- 不做连续时间 scrub、不做录制回放、不做子弹时间
- 不做因果物理模拟（见 §4）
- 不做背包合成
- 不做战斗、不做死亡

## 2. 时间态系统（TimeState）

### 2.1 时刻的定义
- 关卡在配置中声明一个**有序时刻数组** `TIMEPOINTS`，长度 N（MVP：3–4，正式版最多 6）
- 时刻是**离散整数索引** `t ∈ [0, N-1]`，没有中间态
- 时刻有**方向**：索引小的为「过去」，大的为「未来」

```gdscript
# 关卡配置（LevelResource）
@export var timepoints: Array[TimepointDef]   # 长度 N，索引即 t
@export var start_t: int = 2                  # 玩家进入关卡时的初始时刻
@export var unlocked: Array[int] = [0,1,2,3]  # 已解锁时刻；MVP 全开
```

```gdscript
class_name TimepointDef
var id: StringName      # &"T2_RUST"
var index: int          # 2
var label: String       # "锈时·昏"
var roman: String       # "Ⅲ"          —— 色盲安全的主标识
var tint: Color         # 环境色调
var light_angle: float  # 光照角度（度），非色彩区分通道
var ambient_sfx: String # 环境音
var particle: String    # 环境粒子：SPARK / DUST / RUST / ASH
```

### 2.2 全局时刻，不是局部时刻
**MVP 采用全局单一时刻**：切换时刻 = 整个世界（地形、实体、光照、音效）整体切换。玩家的背包是唯一例外。

> 理由：局部时刻（每个物体各自的时间）会让真值表从 N 行爆炸成 N^M 行，且玩家无法建立心智模型。**远景层**才考虑局部时刻。

### 2.3 切换的触发与反馈
| 项 | 规格 |
|---|---|
| 触发 | `A`（上一刻）/ `D`（下一刻）/ `←` `→`；或点击 HUD 刻度尺上的游标。（⚠️ `E` 已绑定 Use，**不可**复用为切时刻） |
| 冷却 | 0.35 s 过渡动画（防连点刷屏），期间输入被吞掉 |
| 边界 | 到头不循环，游标撞到底并播放「卡住」音效（不是静默失败） |
| 反馈通道 1 | **视觉**：全屏色调插值 + 光照角度旋转（0.35 s） |
| 反馈通道 2 | **HUD**：黄铜刻度尺上游标滑动，罗马数字跳动，当前刻度高亮 |
| 反馈通道 3 | **音效**：机械咬合音 + 切换后环境音交叉淡入 |
| 反馈通道 4 | **粒子**：环境粒子整体替换（火星→浮尘→锈屑→落灰） |
| 反馈通道 5 | **物体**：所有形态/位置发生变化的实体播放 0.25 s 变形动画（不做瞬移） |
| 禁止 | 禁止「只有色调变化」的时刻切换 —— 违反支柱 P2 |

### 2.4 当前时刻的持久化
切换时刻**不改变玩家位置**（玩家坐标在所有时刻共用一套网格；若目标时刻玩家脚下格被阻挡，则把玩家推到最近的可通行格并播放提示）。

### 2.5 残影叠加（Observe 长按）规格

**残影是「同时渲染多个时刻的同一实体」**，供玩家建立跨时刻心智模型（支柱 P2 的核心载体）。

| 规则 | 规格 |
|---|---|
| **真值来源** | **唯一**：`resolve_state(e, t)`，**含 Override 改写后的结果**。**禁止**为此开第二套「原始 chain」真值源 |
| **渲染范围** | 对当前视野内每个实体，渲染 `t ∈ 已解锁时刻`，`t == 当前时刻` 的那一层不画残影（它就是实体本身） |
| **跳过条件** | `resolve_state(e,t).pos == POS_VOID` 或 `removed == true` 的时刻**不画**鬼影 |
| **背包物品** | 免疫时刻变化 → **不画残影**，改为在背包格上显示一个「冻结」角标 |
| **标识** | 每个鬼影悬浮一个**罗马刻度角标（Ⅰ/Ⅱ/Ⅲ/Ⅳ）**，与时刻一一对应（同时也是色盲安全通道） |
| **可交互性** | **残影不可交互**（防隔着门用残影拿东西） |
| **性能** | `O(N × 实体数)`，N≤6、实体≤9 → 开销可忽略；**仅在 Override 写入 / 切时刻时置脏重算**，不要每帧 resolve |
| **设置项** | 可关闭（晕动症考量）；可选「残影范围 = 全部时刻 / 仅已访问过的时刻」用于后期长关卡的渐进揭示 |

> **为什么必须显示 Override 后的状态**（不是原始 chain）：
> 1. **一致性** —— 残影只是「同屏渲染多个时刻」，真值来源必须与玩法层同一个函数；两套真值源是 bug 温床。
> 2. **支柱 P2「时间可见」要求残影可信**。若显示原始 chain，玩家搬完砝码后残影仍把砝码画在 (1,2)，残影就开始**说谎**。
> 3. **教学目标 G3「我的操作会影响它的未来」的主反馈渠道就是残影** —— 玩家搬完砝码后长按 Tab，看到它在 T2/T3 都跑到压力板上了，这是本作最核心的顿悟时刻，不能砍。
>
> **防剧透不靠这里**：真正的剧透开关是**时刻锁（L5）** —— 残影**永不显示未解锁时刻**。MVP 全解锁，后续关卡用它做渐进揭示。

## 3. 道具状态链（EntityChain）

### 3.1 四元组
每个实体在每个时刻拥有：

| 字段 | 类型 | 含义 |
|---|---|---|
| `form` | StringName | **形态 ID**（`INGOT` / `KEY_NEW` / `KEY_RUSTY` / `RUST_LUMP`…）。同一实体的不同形态必须共享剪影 |
| `pos` | Vector2i | 世界网格坐标；`POS_VOID = Vector2i(-1,-1)` 表示该时刻**不存在于世界** |
| `available` | bool | 是否可被玩家**持取**（true = 可取） |
| `tags` | PackedStringArray | 交互标签，决定「能用来干什么」（见 3.4） |

### 3.2 数据结构（GDScript 风格，可直接照抄）

```gdscript
const POS_VOID := Vector2i(-1, -1)

class StateFrame:
    var form: StringName = &""
    var pos: Vector2i = POS_VOID
    var available: bool = false
    var tags: PackedStringArray = []
    var note: String = ""        # 可选叙事条目 ID

class TimeEntity:
    var id: StringName           # &"KEY"
    var display_name: String     # "钥匙"
    var anchored: bool = false   # 锚定：不可被玩家移动/取走，且不受覆盖影响
    var silhouette: StringName   # 剪影资源 ID（跨时刻恒定，硬约束）
    var chain: Array[StateFrame] # 长度 == TIMEPOINTS.size()，索引即 t

    # --- 以下均为「实体能力」，不随时刻变化，因此**不放进 StateFrame.tags** ---
    var solid: bool = true            # 占据格是否阻挡通行
    var is_lock: bool = false         # 是否为锁具（可被 USE 开锁）
    var is_receptacle: bool = false   # 是否为容器格（PLACE 吸附目标，见 §6.2.1）
    var writable_fields: PackedStringArray = []  # 锚定物可被玩家写入的字段白名单
```

```gdscript
# 玩家写入的一条覆盖记录
class Override:
    var t_index: int             # 写入发生在哪个时刻
    var entity_id: StringName
    var field: StringName        # &"pos" | &"form" | &"available" | &"removed"
    var value: Variant
    var propagate: StringName    # &"forward"（默认）| &"none"
    var seq: int                 # 全局递增序号，用于撤销与「后写覆盖先写」
```

### 3.3 求解函数（resolve）—— 纯函数，永远是确定的

```gdscript
func resolve_state(entity: TimeEntity, t: int) -> StateFrame:
    var s: StateFrame = entity.chain[t].duplicate()
    if entity.anchored:
        return s                                  # 锚定物只读，玩家无法改写
    var latest: Dictionary = {}
    for o in overrides:                            # overrides 按 seq 升序
        if o.entity_id != entity.id: continue
        if o.t_index > t: continue                 # 未来写入不影响过去（核心！）
        latest[o.field] = o.value                  # 后写覆盖先写
    for f in latest.keys():
        s.set(f, latest[f])
    return s
```

> **这条函数是整个系统的心脏。** 它保证：给定 (实体, 时刻, 覆盖日志)，输出永远唯一确定 → 不存在「算不出来」的悖论。

### 3.4 标签表（MVP 全量）

| 标签 | 作用 | 由谁消费 |
|---|---|---|
| `UNLOCKS:<door_id>` | 可对指定门 USE 开锁 | 门 |
| `PRESSER` | 放在压力板上能触发 | 压力板 → 闸门 |
| `BLOCKING` | 占据格不可通行 | 寻路 |
| `HOT` | 不可取，反馈「太烫」 | 持取 |
| `IMMOVABLE` | 不可取，反馈「锈死/太重」 | 持取 |
| `OCCLUDED` | 不可见不可取，反馈「被掩埋」 | 持取 + 渲染 |
| `TOO_THICK` | 不可 USE 清除，反馈「太粗了」 | 使用 |
| `PULLABLE` | 可 USE 拔除 | 使用 |
| `FRAGILE` | USE 于门时会折断（一次性负反馈） | 门 |
| `JUNK` | 无用途，仅供叙事 | — |

> **硬规则**：`IMMOVABLE` / `OCCLUDED` / `HOT` **只影响「玩家能否持取」，绝不影响「占位/压感/阻挡」**。若物体在压力板上锈死，它照样压住板子 —— 这条必须在 GDD 与代码注释里同时写明，否则会出现「T2 砝码锈死了为什么机关还开着」的 bug。

## 4. 因果与依赖规则

### 4.1 模型：**只读历史 + 玩家覆盖层**
- 时间线（实体的 `chain`）是**预设的只读数据**，由策划写在真值表里，**不做物理模拟、不做推导**
- 玩家的操作写入 `overrides` 覆盖层
- 世界呈现 = `resolve_state(实体, 当前时刻)`

> 这不是偷懒，这是**悖论免疫力**：因为历史是常量，任何时刻的状态都是可计算的，系统绝不崩溃。

### 4.2 允许改变过去吗？允许，但只影响未来
| 方向 | 规则 |
|---|---|
| **向未来（t 增大）** | ✅ 传播。所有玩家写入默认 `propagate = "forward"` |
| **向过去（t 减小）** | ❌ **绝不传播**。硬性禁止（这是祖父悖论的唯一防线，写进代码断言） |
| **同时刻** | ✅ 立即生效 |

### 4.3 级联规则（三条，穷尽）

| 场景 | 写入内容 | 级联效果 |
|---|---|---|
| **C1 位移**（持取后放下 / 推移） | 在 `t_k` 写入 `pos = L`，forward | 所有 `t > t_k` 的 `pos = L`（若该时刻 `form ≠ VOID`）；`t < t_k` 保持链原值 |
| **C2 取离世界**（持取进背包且不放回） | 在 `t_k` 写入 `pos = POS_VOID`，forward | 所有 `t > t_k` 该实体**缺席**；背包中持有拾取瞬间的 `form`（冻结） |
| **C3 形态转换**（拔除藤蔓、折断钥匙、熔炼等） | 在 `t_k` 写入 `form = X`，forward | 所有 `t > t_k` 的 `form = X`，覆盖链原值 |

- **放回世界（PLACE）**：只追加 **C1（`pos = L`）**，**不写 `form`** —— 物件一旦离手回到世界，就**重新受时间支配**，继续沿链演化。
- **锚定物**（`anchored = true`）：不进覆盖层，玩家永远改不动（门、压力板、地形、熔炉、钥匙台）。例外：显式声明 `writable_fields` 的锚定物可被写指定字段（如 `VINE.removed`、`GATE.open`）。

#### 4.3.1 冻结范围裁决（v0.2 修订 —— 原 C3 表述有误，以此为准）

> **冻结只在背包里生效。**
> `form` 的冻结**只在手持期间**存在；一旦 PLACE 回世界，`form` 交还给状态链。

| 动作 | 是否写 `form` | 结果 |
|---|---|---|
| 持取 TAKE | —（冻结进背包） | 手持物保留拾取瞬间的 `form` 与 `tags`，**切时刻不变** |
| 放置 PLACE | ❌ **不写** | 只写 `pos`；此后 `form` 沿链演化（T1 放下的砝码，在 T2 变成 `WEIGHT_SEIZED`） |
| 开锁 USE（锁具） | ✅ **写**（携带形态） | 钥匙留在锁孔，形态保持插入瞬间的样子（见下方叙事说明） |

**为什么改**：原 C3 写「放下 = 写入 `form=` 携带形态」，这与本作第一 mantra「世界上的东西会随时间变，我手上的东西不会」**自相矛盾** —— 若放下后仍冻结，等于「世界上的东西也不变了」。改为「离手即重新受时间支配」后，mantra 变得完全自洽且更好教：

> **新形态只在你手上保鲜；一放回世界，它就重新开始经历时间。**

**关卡 1 不受影响**：关卡文档 §5.2 已规定砝码四个形态**全部带 `PRESSER`**，因此无论 T2 砝码是 `WEIGHT_OK`（冻结）还是 `WEIGHT_SEIZED`（沿链），压力板都被压住 → 闸门都开 → 关卡均可解。真值表无需改动。

**锁孔里的钥匙保持崭新 —— 这是刻意的叙事彩蛋，不是 bug**：USE 开锁时写入 `form = 携带形态`，所以在 T3（万物成灰）时，锁孔里仍留着一把你从过去带来的崭新钥匙。它是玩家时间旅行的**物证**，请保留此行为。

### 4.4 一个必须写进代码注释的例子（防误解）
> 玩家在 **T1** 取走钥匙 → T2、T3 的钥匙 `pos = POS_VOID`（缺席），但 **T1 本身仍显示钥匙**（写入点自身生效），**T0 完全不受影响**。
> 玩家随后在 **T3** 放下这把钥匙 → T3 出现钥匙，T2 仍然**空着**。
> **这不是 bug**：你从 T1 抽走了它，历史里 T2 就没有钥匙；你在 T3 放下的是一件新插入的物品。UI 需在放下时给一句提示语「它将从此时开始存在」。

### 4.5 如何避免「悖论无解」
1. **结构上免疫**：`resolve_state` 是纯函数 → 永远有解可算
2. **悖论只表现为关卡死局**，由死锁谓词检测（§7.1），不表现为系统错误
3. **死锁一定可撤销**（§7.2）→ 玩家永远能出来
4. **关卡设计约束**：任何关卡不得设计「一次性不可逆的破坏」而没有兜底路径（教学关：钥匙折断后 T1 仍有崭新钥匙可取 → 天然自愈）

## 5. 时间切换的限制与代价（防无脑穷举）

| # | 限制 | 规格 | MVP 关卡 1 取值 |
|---|---|---|---|
| L1 | **时砂 Hourglass** | 切换时刻消耗 `|Δt|` 点；容量由关卡配置；耗尽不可切换（只能撤销/重置）；撤销**全额返还** | 容量 12，实际最优解仅耗 2 点 |
| L2 | **背包容量** | 同时手持实体数上限；超限拒绝持取并提示 | **2** |
| L3 | **形态锁** | `HOT` / `IMMOVABLE` / `OCCLUDED` / `TOO_THICK` 使该时刻该动作**不可执行**（不是失败，是灰掉 + 反馈原因） | 见真值表 |
| L4 | **锚定物** | `anchored = true` 的实体不可被玩家移动/取走/改形态 | 门、闸门、压力板、熔炉、钥匙台 |
| L5 | **时刻锁** | 关卡可声明部分时刻初始锁定，需「时间裂纹」道具解锁；锁定时刻在刻度尺上显示为断裂刻度 | 关卡 1 全解锁；正式关卡启用 |
| L6 | **切换冷却** | 0.35 s 过渡，输入被吞 | 固定 |
| L7 | **残影为观察态** | 残影叠加只显示，**不可交互**，防止玩家用残影隔着门拿东西 | 固定 |

#### 5.1 时砂是**派生量**，不是计数器（实现必读）

时砂**不存一个可变计数器**，而是从当前操作日志实时派生：

```gdscript
func sand_remaining() -> int:
    var spent := 0
    for a in action_log:                 # action_log = 未被撤销的操作序列
        if a.type == &"SHIFT":
            spent += abs(a.from_t - a.to_t)
    return level.sand_capacity - spent
```

由此得到三条结论，无需任何额外「退还」逻辑：

1. **撤销 = 该操作从未发生**。撤销只是从 `action_log` 弹出记录 → 时砂**自动**回来。切换时刻的消耗与操作消耗**同源同算**，不存在「分开结算」。
2. **时砂永不负数**：`spent > capacity` 时，SHIFT 在**输入层就被拒绝**（反馈「沙漏空了」），因此超限在构造上不可能发生，不需要 clamp。
3. **撤销与重置永远免费且永远可用**，不受时砂约束 —— 这是防软锁死的硬保证。

> **设计依据**：支柱 P3「永不惩罚」。若撤销不退还切换消耗，玩家「探索 → 撤销」会被扣税，最终可能卡在 0 砂却又必须切换的软锁里 —— 这直接违反 P3。
> **时砂的真正作用**是约束**最终留下的那条解法路径**的效率（配合「最少切换次数」评星），而不是给探索收税。防穷举的主要压力由 L2 背包容量 / L3 形态锁 / L4 锚定 / L5 时刻锁 / L6 切换冷却承担。

> **设计红线检查**：限制不得让玩家「算不清」。L1/L2 必须在 HUD 上常驻可见（沙漏图标 + 背包格），不可隐藏。

## 6. 与场景 / 环境的交互规则

| 对象类型 | 是否锚定 | 时刻响应规则 |
|---|---|---|
| **门 / 锁（GATE）** | ✅ 锚定 | 开启状态是**覆盖写入**，`propagate = forward`。在 T1 开的门，T2/T3 也是开的；T0 不受影响。开锁消耗手持钥匙（钥匙留在锁孔，`pos` 写入门格） |
| **压力板（PLATE）** | ✅ 锚定 | **派生状态，实时判定**：`pressed(t) = ∃ 实体 e，resolve(e,t).pos == plate.pos 且 tags 含 PRESSER`。不写入覆盖层 |
| **闸门 / 升降机关（GRATE）** | ✅ 锚定 | 同样是派生：`open(t) = plate.pressed(t)`。随时刻即时变化，可看到「切到 T0 它就落下了」 |
| **容器 / 箱柜** | ✅ 锚定 | 内容物是独立实体，容器只提供 `pos_slot`；内容物 **不跟随容器移动**（简化），但**跟随时刻**（按自己的链） |
| **开关 / 闸柄** | ✅ 锚定 | 扳动写入覆盖，forward 传播 |
| **静态障碍（藤蔓、落石、坍塌门）** | ✅ 锚定 | 形态与阻挡由链定义；`PULLABLE` 的可被 USE 清除（写入 `removed = true`，forward）；`TOO_THICK` 不可清除 |
| **地形 / 墙体** | ✅ 锚定 | MVP 中**地形无时间链**（全时刻相同），减少真值表爆炸；远景层再开放 |
| **可搬运道具（钥匙、砝码）** | ❌ 自由 | 遵循 §4.3 的 C1/C2/C3 |

### 6.1 判定的优先顺序（实现必读）
```
1. 取 resolve_state(entity, current_t)
2. 检查 tags 是否允许该动作（形态锁）→ 不允许则拒绝并给原因反馈
3. 执行动作 → 追加 Override（seq++）
4. 重算所有派生状态（压力板 → 闸门）
5. 重算死锁谓词
6. 播放反馈（动画 + 音效 + 图标，三通道冗余）
```

### 6.2 目标格选择规则（UX · 三个动词必须一致）

> **背景**：`take` 与 `use` 都有「面向格优先 → 扫描四邻自动转向」的兜底，但 `place` 曾**漏掉兜底**，导致玩家无法把砝码放上压力板（关卡 1 因此无法通关）。这不是数值问题，是**动词一致性**问题。

**三条硬性 UX 规则：**

| # | 规则 | 说明 |
|---|---|---|
| **U1** | **走路时更新朝向** | 每移动一格，把 `_facing` 设为该步的移动方向。玩家走到压力板旁边时自然面向它，符合直觉；也是 take/use 面向格正确的前提 |
| **U2** | **`place` 必须有与 take/use 相同的兜底扫描** | 面向格无效时，按 `[面向, 下, 右, 上, 左]` 扫描四邻，选中第一个**合法放置格** |
| **U3** | **放置吸附「容器格」（`is_receptacle`）** | 容器格**永远优先于空地**。避免把砝码放到旁边地板上而玩家以为机关坏了 |

**为什么必须 U1 + U2 都做**：只做 U2 的话，若面向格恰好是一块合法空地，仍会放到空地而不是压力板；只做 U1 的话，玩家从 (6,1) 走到 (6,2) 时朝向正确，但若从其他方向进入仍会出错。两者互补才稳。

#### 6.2.1 U3 的数据模型：`is_receptacle` 字段（v0.3 定稿）

> **不要用「该格存在 anchored 实体」来推断容器格。** 该信号会严重过匹配：
> `is_blocked()` 对 **GATE 开启时、GRATE 开启时、VINE 在 T0/T1（非 BLOCKING）、EXIT 在 T2（INTACT）** 都返回「可通行」，而它们**全是 anchored** —— 会被误判成容器格。关卡 1 里它只是**恰好**在 (6,2) 这一格上没撞上别的 anchored 实体而侥幸成立，换个布局立刻失效。

**正确做法：在 `TimeEntityData` 上加显式布尔字段**（与 `anchored` / `solid` / `is_lock` 同级）：

```gdscript
## 是否为「容器格」——放置（PLACE）时的**吸附目标**。
## 与 anchored/solid/is_lock 同级：是**实体能力**，不是**时刻状态**。
## 因此**不放进 StateFrame.tags**（tags 逐时刻变化；容器性不随时间变化，
## 放进 tags 就得在 N 个帧里重复写 N 遍，极易漏写某一帧）。
var is_receptacle: bool = false
```

**关卡 1 取值**：仅 `PLATE` 为 `true`；`GATE` / `GRATE` / `VINE` / `EXIT` / `STAND` / `FORGE` / `KEY` / `WEIGHT` 全部 `false`。
**后续扩展**：箱子、插槽、祭坛、插座等一律设 `true`，无需改判定逻辑。

#### 6.2.2 放置目标选择算法（`resolve_place_target`，可直接照抄）

```
候选集 = [面向格] + 四邻(下,右,上,左)，去重，面向格排最前
1. 候选中 is_receptacle == true 且 not is_blocked(cell, t)  → 取第一个
2. 否则：面向格 若合法(inside 且 非墙 且 not blocked)      → 取面向格
3. 否则：四邻中第一个合法格（下,右,上,左）
4. 否则：失败 → 反馈「这里放不下」
```

> **注意**：容器格**不要求可通行**（箱子可以踩不上去但仍然能放进东西），所以判定里**不要**加 `not is_blocked` 之外的可通行条件。已占用的容器格会被 `is_blocked` 挡掉（重物本身 `solid`），自然跳过。

#### 6.2.3 已知取舍与逃生口
- **取舍**：U3 是「吸附」语义，因此**玩家无法把东西放到紧贴容器格的空地上**（总会被吸到容器上）。MVP 无此需求，可接受。
- **逃生口**：需要纯空地放置时，站到**不与任何容器格相邻**的格子即可。若将来确有高频需求，再加「按住修饰键取消吸附」，**不新增动词**。

#### 6.2.4 关卡设计约束（新增，供后续关卡遵守）
1. 容器格**至少 2 个相邻可站格**（关卡 1 的 (6,3) 只有 1 个，是这个 P0 的放大器）
2. 容器格**不要**与「开启后会变为可通行的门/闸」相邻，避免吸附歧义

## 7. 失败态、撤销与提示系统

### 7.1 失败态判定（本作没有 Game Over，只有「死局」）
- **通用死锁谓词**（伪代码）：
```gdscript
func is_deadlock() -> bool:
    for req in level.requirements:          # 例：{tag:"UNLOCKS:GATE", target:"GATE"}
        var satisfiable := false
        for t in unlocked_timepoints:
            var tags := 背包内全部 form 的 tags
            for e in level.entities:
                tags += resolve_state(e, t).tags
            if req.tag in tags: satisfiable = true
        if not satisfiable: return true     # 任何时刻都凑不出所需标签 → 死局
    return false
```
- 触发表现：**不弹失败画面**。表现为 HUD 沙漏变灰 + 一句轻提示「这条时间线似乎走不通了」+ 撤销按钮高亮呼吸
- 关卡 1 经设计**不存在真死局**（唯一破坏性操作「钥匙折断」不影响 T1，天然自愈）

### 7.2 撤销
| 能力 | 规格 |
|---|---|
| 单步撤销 `Z` | 弹出 `overrides` 中 `seq` 最大的一条，并**回滚它派生出的 forward 传播记录** |
| 时间轴撤销 | 长按 `Z` 打开操作时间轴，可拖到任意历史节点（含时刻与位置一并回滚） |
| 重置时刻 | 清空 `overrides`，回到关卡初始时间线；返还全部时砂 |
| 代价 | **零代价**，全额返还时砂；撤销次数不限 |

> 实现要点：forward 传播的记录必须带 `parent_seq`，撤销父记录时级联删除子记录。

### 7.3 提示系统（3 级，绝不直接给答案在前两级）

| 级别 | 形态 | 关卡 1 示例 |
|---|---|---|
| **L1 · 指向** | 高亮一个区域/物体，不给理由 | 「留意钥匙台上那把钥匙。」（高亮 (3,2)） |
| **L2 · 缩窄** | 说明「性质差异」，不给操作 | 「这把钥匙并不是一直都是锈的。」（高亮时刻刻度 Ⅱ） |
| **L3 · 明示** | 直接给出操作序列中的一步 | 「切到『新光·昼』，取走崭新的钥匙。」 |

**触发条件**
| 触发 | 阈值 |
|---|---|
| 主动 | 玩家按 `H`，逐级解锁 |
| 被动 L1 | 同一时刻停留 90 s 且无「有效进展」（无新 Override、无门开、无首次进入新格） |
| 被动 L2 | 首次提示后 180 s 仍无有效进展，或第 2 次主动请求 |
| 被动 L3 | 累计 360 s 无有效进展，或第 3 次主动请求 |
| 冷却 | 各级提示之间至少间隔 45 s，避免刷屏 |

## 8. 可扩展谜题语汇（时间谜题原子，8 种）

> 每种原子 = 一句话定义 + 具体例子 + 真值表长什么样。关卡 1 用到 1/2/3/4/5。

### A1 · 锈蚀递进（Decay）
**定义**：同一实体沿「完好 → 磨损 → 失效 → 无用」单向劣化，玩家必须回到早期时刻取得可用形态。
**例子**：金属锭 → 崭新钥匙 → 生锈钥匙（一拧就断）→ 锈块。
**真值表形态**：

| 时刻 | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| KEY | INGOT / `HOT` | **KEY_NEW / `UNLOCKS:GATE`** | KEY_RUSTY / `FRAGILE` | RUST_LUMP / `JUNK` |

### A2 · 位移搬运（Relocation）
**定义**：玩家在过去移动一件物品，移动结果沿时间线向前保留，从而改变未来的空间关系。
**例子**：黄铜砝码在 T1 是完好的可被搬到压力板；T2 已锈死在地搬不动。玩家必须在 T1 搬，才能让 T2 的闸门开着。
**真值表形态**：

| 时刻 | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| WEIGHT 基线 | MOLTEN / `HOT` | **OK / 可取** | SEIZED / `IMMOVABLE` | BURIED / `OCCLUDED` |
| 玩家在 T1 搬后 | — | pos=(6,3) ✅ | pos=(6,3)（传播）✅ | pos=(6,3)（传播）✅ |

### A3 · 生长衰变（Growth / Wither）
**定义**：生物类障碍随时间先长大或后枯萎，通行性在某个时刻出现「窗口」。
**例子**：藤蔓 T0 幼苗 / T1 幼藤（可拔除）→ T2 茂密（挡路且拔不动）→ T3 枯藤（仍封路）。玩家必须在 T2 之前拔掉。
**真值表形态**：

| 时刻 | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| VINE | SPROUT / `PULLABLE` `BLOCKING` **阻挡** | YOUNG / `PULLABLE` `BLOCKING` **阻挡** | THICK / `TOO_THICK` **阻挡** | WITHERED / **阻挡** |
| 玩家在 T1 拔除后 | SPROUT（不受影响） | removed ✅ | removed（传播）✅ | removed（传播）✅ |

### A4 · 占位阻挡（Occupancy）
**定义**：某物在某时刻占据关键格，玩家需消除它的占位（搬走 / 拔除 / 等待其消失）才能通行。
**例子**：坍塌的横梁在 T2 堵住走廊，T0/T1 尚未塌。
**真值表形态**：

| 时刻 | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| BEAM | 不存在（通行） | 完好在梁上（通行） | **坠落堵路 / `BLOCKING`** | 堵路 |

### A5 · 状态冻结 / 携带（Carry-over）
**定义**：手持物免疫时刻变化，玩家把「过去的好形态」偷渡到「现在」使用。
**例子**：在 T1 拿到崭新钥匙，切到 T2 开锈门 —— 尽管 T2 的钥匙已经锈断。
**真值表形态**：

| | T1 拾取 | 切到 T2 | 使用 |
|---|---|---|---|
| 背包 | `KEY_NEW`（冻结） | `KEY_NEW`（**不变**） | 消耗，GATE.open=true（forward） |

### A6 · 时序窗口（Timing Window）
**定义**：某机关需要**在两个不同时刻各操作一次**才能维持状态，迫使玩家来回切换。
**例子**：双闸水闸 —— 在 T1 扳下左闸、在 T2 扳下右闸，两闸必须同时处于下位，门才开（单独任一时刻都不满足）。
**真值表形态**：

| 时刻 | T1 | T2 |
|---|---|---|
| 左闸 | 可扳 → down（forward） | down |
| 右闸 | up（尚未安装） | 可扳 → down |
| 门 | 关（缺右闸） | **开** |

### A7 · 因果悖论解锁（Paradox Unlock）
**定义**：「消除」未来的某物反而解锁通路 —— 逆向直觉的顿悟点。
**例子**：蓄水池在 T2 装满水，重量压死了下方的翻板机关（通道封死）；玩家在 T1 打开排水阀 → T2/T3 池子空了 → 翻板弹起 → 通道打开。
**真值表形态**：

| 时刻 | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| 阀门 | 未装 | **可开（写入 open，forward）** | open（传播） | open（传播） |
| 池水 | 满 | 满 | 满 → **空**（派生） | 空（派生） |
| 翻板 | 开 | 开 | 关 → **开** | 开 |

### A8 · 回声残留（Residue）—— 叙事/提示专用
**定义**：某物在过去留下的痕迹在未来仍然可见，用于提示与叙事，不可交互。
**例子**：T0 工匠在门框上刻的字，在 T3 只剩模糊刻痕；玩家观察刻痕得到密码。
**真值表形态**：

| 时刻 | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| 刻痕 | 清晰全文 | 清晰 | 半磨损（可读 2/3 字） | 仅剩 2 字（谜面） |

## 9. 验收标准（给架构师与 QA）

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | `resolve_state` 是纯函数，同输入必同输出 | 单元测试：随机 Override 序列 × 全部时刻 |
| 2 | 任何 Override **绝不**影响 `t < t_index` 的状态 | 断言：写入后重算全部更小 t，逐字段比对基线 |
| 3 | 撤销可回到任意历史节点，且状态与当时逐字段一致 | 快照比对测试 |
| 4 | 撤销与时砂全额返还，无负数、无泄漏 | 资源账本测试 |
| 5 | 五个动词覆盖关卡 1 全部操作，无第六动词 | 操作日志审计 |
| 6 | 时刻切换具备 ≥3 条非色彩区分通道 | 关掉色彩后仍可分辨（人工盲测） |
| 7 | 关卡 1 按标准解法可通关，且最少步数符合设计 | 自动化可解性验证脚本 |
| 8 | `IMMOVABLE/OCCLUDED` 不影响占位与压感 | 专项用例：砝码在压力板上锈死后机关仍开 |
