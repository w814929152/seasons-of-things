### 窗口尺寸 / 画面缩放（`src/ui/window_scaler.gd`）

游戏**一切**都按 **1248×908 的「设计分辨率」**绘制 —— 13×8 网格 × 每格 96 px，横向正好铺满 1248，
HUD 占顶部 140 px。所以「让场景 / 道具更大更清晰」的杠杆，是把整块设计画布**等比放大**；
而「房间本身要更大」则要靠**扩网格 + 扩画布**（见 §8 的 v4 小节）。

启动时 `WindowScaler.apply()` 会把窗口设成「屏幕可用区域内放得下的最大等比尺寸」并居中：

| 常量 | 默认 | 含义 |
|---|---|---|
| `DESIGN` | `1248×908` | 设计分辨率，须与 `project.godot` 的 `viewport_width/height` 一致 |
| `MAX_SCALE` | `2.0` | 缩放上限（4K 屏下取到 2.0 → 窗口 1920×1280） |
| `SCREEN_FILL` | `0.92` | 自动模式下最多占屏幕可用区域的比例 |
| `FORCE_SCALE` | `0.0` | **改成正数即写死倍率**（如 `1.5` / `2.5`）；`<= 0` 为自动 |

因为 `stretch/mode = "canvas_items"`，放大是**按窗口分辨率重新光栅化**的清晰缩放（不是拉位图），
道具与文字同步变大且不糊。headless（测试 / 扫参）下不会动窗口。

## 2. 怎么操作

| 键              | 动词     | 说明                               |
| -------------- | ------ | -------------------------------- |
| `↑` `↓` `←` `→` | **移动** | 走一格；**按住不放会连续走**（首步立即响应，之后约 0.13 s 一格） |
| `A` / `D`      | **切换** | 上一刻 / 下一刻（各消耗 1 点时砂）             |
| `空格`           | **持取** | 把面前可取之物拿进背包（容量 2）                |
| `Q`            | **放置** | 把背包顶部的东西放到面前的格子（压力板 / 空地）        |
| `E`            | **使用** | 开锁 / 拔藤蔓                         |
| `Tab`          | **观察** | 开关**残影叠加**（同物体四个时刻半透明同屏）+ 打印物件描述 |
| `Z`            | **回溯** | 单步撤销（免费、全额返还时砂、不限次数）             |
| `H`            | —      | 提示（L1 指向 → L2 缩窄 → L3 明示）        |
| `R`            | —      | 重置时刻（回到关卡初始时间线，免费）               |
| **鼠标左键**       | —      | 点格子 → 自动寻路走过去；**按住拖动**可实时改目的地（RTS 式持续走） |
| **鼠标移动**       | —      | 悬停任意格 → 地上画出**路径预览**（可达=黄铜足迹，不可达=暗红叉角） |

> ⚠️ `E` **只**绑定 Use，绝不复用为切时刻（概念文档 §5 的键位冲突修正）。
> ⚠️ 方向键让给**移动**之后，切时刻**只**剩 `A` / `D`（原来还能用 `←/→`）。

### 移动语义（第八轮改造，四条硬规则）

1. **逐格推进**：点一下不会瞬移。精灵沿**一串相邻格**前进，**每真正走到一格**，逻辑坐标
   `tc.player_pos` 才前进一格 —— 所以「人没到就不会先结算」：点出口的瞬间不会通关，
   人还没挪过去时按 `E`/`Q`/空格也不会按目标格判定。
2. **不可能斜穿墙角**：路线永远是 4 邻接的格子序列，即使中途改目的地也只在**当前这一步走完**
   之后再拐弯；未过半格就改目标则先退回本格格心（不浪费那半格）。
3. **整段移动 = 一步撤销**：连续移动（含长按方向键、拖动鼠标）只入栈**一条**撤销记录。
4. **状态变化即取消**：切时刻 / 撤销 / 重置 / 持取 / 放置 / 使用都会先取消在途移动并把精灵
   吸回逻辑格（切时刻可能因脚下被封而把玩家挤到别格，必须重新对齐）。


### HUD 常驻（GDD §5 设计红线）

- **黄铜刻度尺**：罗马刻度 Ⅰ–Ⅳ + 游标；点击刻度可直接跳到该时刻
- **时砂**：`12 / 12`，耗尽变灰
- **背包**：2 格，显示**冻结的形态**（切时刻不变 —— 这是 A5「携带穿越」的可视证据）
- **撤销 / 重置 / 提示** 三个按钮

### 通关条件

在 **T2（锈时·昏 · 刻度 Ⅲ）** 站上出口门格 **(11,1)**。

最短解：**7 步操作、2 次切换、耗 2 点时砂。**

<details>

<summary>标准解法（关卡文档 §7，剧透）</summary>

1. T2 取锈钥匙 → USE 于铁栅 → **折断**（设计好的教学负反馈；T1 的崭新钥匙不受影响）

7. T1 把砝码放到压力板 (9,3)
8. 切回 **T2** → 闸门已开 → 走到 (11,1) 通关

## 6. 需要主理人裁决的两处偏离

实现时发现 GDD 内部有两处**互斥规格**，已选一边落地并在架构文档披露：

1. **锚定物的可写字段**（GDD §4.3「锚定物玩家永远改不动」 vs GDD §6「门的开启是覆盖写入」「藤蔓 PULLABLE 可清除」）  
   → 用 `TimeEntityData.writable_fields` 白名单化解：`GATE` 只可写 `open`，`VINE` 只可写 `removed`，自由道具可写 `pos/form/available/removed`。**关卡可解性依赖此取舍。** → architecture §12.3-D1
2. **放置是否冻结形态**（GDD §4.3 C3「form = 携带形态」 vs 关卡文档 §9.1/§11-8「砝码放上板后 T2 仍是锈死」）  
   → 选了**只写 pos、不冻结 form**；冻结完全由背包承担（这才是 A5 的核心）。 → **ADR-006**

## 7b. 陀螺对战（`tops/`）—— 同工程内的第二个项目，Phase 1 最小可玩切片（物理版 + 2.5D）

与《物候》并存，**不共用任何逻辑**。核心机制设计见 `design/tops/core_mechanic_design.md`。

### 玩法（发射制 · 进场后完全交给物理）

1. **发射阶段**：你在场地边缘待命——鼠标 / `←→` 调发射方向，按住 `Shift` 或左键蓄力，**松手即进场**。
2. **战斗阶段**：进场后**无法操控**，你的陀螺只靠发射初速 + 自转进动漂移 + 物理碰撞运动；
   AI 对手保留主动推进。全部策略压缩进「发射」这一次决策（角度 × 力度）。
3. 5 人混战，最后一个还在转的赢；60 s 起缩圈，单局目标 3–5 min。`R` 重开。

### 架构（物理版 + 2.5D 分工）

- **`tops/tops_top.gd`**：`TopTop extends RigidBody2D` —— 平移运动、碰撞检测与弹开**全部交给 Godot 内置物理**
  （`gravity_scale=0` 俯视无重力 · `can_sleep=false` 防 apply_force 失灵 · CCD 防穿透 · PhysicsMaterial bounce 0.70）；
  进场前 `freeze + collision_mask=0` 待命，发射时解冻并给初速
- **`tops/tops_rules.gd`**：`TopsRules` 纯函数规则层 —— 转速经济（Δspin 伤害 / 摩擦交换转速 /
  撞墙损耗 / 衰减 / 击倒回血 / AI），零渲染依赖、可 headless 断言；§4.2「伤害 ≠ 击飞」铁律在此层保住
- **`tops/tops_main.gd`**：发射→战斗两阶段状态机；24 段 StaticBody2D 圆环边界，缩圈靠内移墙段
  （不用缩放节点，Godot 2D 物理对缩放静态体不可靠）
- **2.5D 视角**：物理平面仍是纯 2D（碰撞判定不变），绘制时经 `TopsArt.project()` 把 y 压扁成椭圆地面，
  陀螺加视觉高度 + 落地阴影，并按物理 y 排序绘制 → 斜俯视伪 3D，零外部美术资源

## 7. 一句话玩法心法

1. **世界上的东西会随时间变，我手上的东西不会。**
2. **我动过的东西，会影响它以后的样子，不会影响它以前的样子。**
3. **有些事只能在特定的那一刻做**（太烫 / 锈死了 / 长太粗了）。

## 8. 场景视觉设计（v2 可读性 → v3 连续场景 → v4 房间放大）

> 演进三轮，都是**看图诊断**（`tools/shot.gd` 渲染 + `tools/crop.gd` 放大取样），不靠猜。
>
> **v2（可读性）**：用户反馈「场景可读性差」。定位四个硬伤：① 地板是饱和暖棕，而道具也全是暖色
> （木台 / 黄铜 / 锈）→ **图底不分**；② 墙是同色相平涂色块 → **没体积**；③ 地板上那圈白色"受光边"
> 读起来像选中框 → **纯噪声**；④ 地板色由时刻 tint 现算 → **对比度每换一个时刻就变一次**。
>
> **v3（连续场景）**：用户反馈「改成正常的 2D 游戏场景，而不是一个格子一个格子」。
> 根因诊断：**v2 为了可读性给每个格子都画了轮廓**（棋盘地板 + 逐格砖缝斜切墙块）——
> 逻辑网格（10×5）被画成了**视觉网格**，场景读起来像一张表格，而不是一间屋子。
> v3 的目标因此是：**保留逻辑网格，但把它从画面里彻底隐藏**。
>
> **v4（房间放大）**：用户反馈「增加房间大小，给人一种更像房间的感觉」。诊断：v3 的**去格子感对了**，
> 但房间本身太小 —— 10×5 里 6 个格子被中隔断吃掉，可走区域只剩 3×3，读起来是"过道"不是"房间"。
> v4 因此**扩关卡并重新设计布局**：网格 **10×5 → 13×8**（地面格数约 **2.7 倍**），
> 画布 **960×640 → 1248×908**。灯光 / 调色 / 明度阶梯 / 去格子感四招**全部照旧**，只放大尺幅。

### 三条恒定原则（v2 立、v3 沿用）

1. **图底分离**：环境是**冷色低饱和**（石板 / 铁灰）；暖色（黄铜 / 锈 / 木 / 藤）**全部留给道具**
   → 道具永远是画面里最亮、最暖的东西。
2. **对比恒定**：调色板是**基色**、不随时刻改色。时刻的"色温分期"做成一条**乘法调色**
   （`EnvironmentLayer._recompute_light()` → `light_color()`），统一施加到**环境与道具**上
   （道具用 `modulate` 接收，避免"只有地板变色、道具像贴纸"）。乘法只等比压暗 + 偏色，
   不像加色叠加那样把对比度冲平。
3. **光向可见**：墙块的**交界斜面**、**墙投影**与道具的**落地阴影**都按 **−光照方向**取向。
   四个时刻的光角 15° / 90° / 300° / 350° → 受光面与影子方向明显不同，**不依赖任何颜色**
   就能判断当前是第几刻（概念文档 §7 要求 ≥2 条非色彩通道，这是其中最直观的一条）。

### v3 的"去格子感"四招

| # | 做法 | 为什么它不产生格线 |
|---|---|---|
| ① | **地板 = 一整片**：所有非墙格铺同一基色，**不画任何格线 / 棋盘** | 相邻格之间没有任何缝 → 连成一片地面 |
| ② | **墙 = 连续实体块**：逐格填同色、**不描边** | 相邻墙格自然并块，不出现"每格一个方块" |
| ③ | **斜面与轮廓只画在"墙 ↔ 非墙"交界边上** | 得到的是**一圈连续的外轮廓**，而不是 13×8 个小方框 |
| ④ | **靠光与影给体积**：墙根环境遮蔽 (AO) + 沿 −光向的整片投影 + 交界受光/背光斜面 | 没有网格线，体积感全部由光影承担 |

> ⚠ 实现要点：墙体投影是"把每个墙格沿 −光向平移同一距离"，**同一平移量作用在互不相交的格子上，
> 平移后依然互不相交** → 半透明矩形并起来不会有重叠接缝（这是能放心用 alpha 铺影子的原因）。

### v4 的"房间放大"（10×5 → 13×8）

**为什么必须扩网格、不能只缩放**：v3 里房间已经铺满 960px 画布宽度（10 格 × 96px = 960），
所以"变大"= **扩网格 + 扩画布**，不可能靠缩放（缩放只会让格子更大、更少，房间反而更挤）。

| 项 | v3（10×5） | v4（13×8） |
|---|---|---|
| 设计分辨率 | 960 × 640 | **1248 × 908**（13 × 96 + HUD 140） |
| 玩家起点 | (2,3) | (3,5) |
| 西厅（工匠前厅） | 3×3 格 | **6×6 格**（真的宽敞） |
| 中隔断墙 | x=4,5 断开的两段 | **2 宽 × 5 高**（x=7,8 × y=2..6） |
| 东厅（出口厅） | 3×3 格 | **3×6 格**（压力板凹室 + 闸门后小厅） |
| 大门 GATE | (4,1) | (7,1) |
| 藤蔓 VINE | (5,1) | (8,1) |
| 闸门 GRATE | (7,2) | (10,2) |
| 压力板 PLATE | (6,3) | (9,3) |
| 出口 EXIT | (8,1) | (11,1) |

**布局改版时逐条重验的拓扑约束（4 个谜题语义完全不变，只平移坐标）**：

1. **唯一咽喉**：顶层 y=1 只留 `(7,1) 大门 → (8,1) 藤蔓`（(7,0)(7,2)(8,0)(8,2) 均实墙）→ 东西两厅除此以外**完全不连通**。
2. **出口只经闸门可达**：`(10,1)` 实墙封住出口北邻 → 出口 (11,1) 只能从 (11,2) 进入，而 (11,2) 只接闸门侧。
3. **压力板凹室只从南北进**：`(10,3)(11,3)` 把 (9,3) 关成只从 (9,2)/(9,4) 进出的凹室 —— 保留原 `(6,2)` 的教学几何。
4. **(9,2) 与它的旧身 (6,2) 四邻同构**：北 (9,1) 地板 / 南 (9,3) 压力板 / 东 (10,2) 闸门 / 西 (8,2) 墙
   → 所以 P1–P6 放置专项用例（见设计文档 §11.1）**语义全部保持**，只换坐标。

> ⚠ 放大后 `(3,1)` 不再"一词两义"：在 10×5 里它同时是**钥匙台北邻**（取钥匙站）与**大门西邻**（开门站）；
> 放大后大门移到 (7,1)，两者分别是 **(3,1)** 与 **(6,1)** —— 测试里必须分开写，否则 `take/use` 的相邻判定会漏。

**墙格接缝核查**：墙体逐格 `draw_rect` 都落在 96px 整数倍上，像素探针沿顶墙整行、中隔断整列逐像素取样，
**所有边界像素亮度完全一致**（T1 均为 `0.3090`）→ 墙是真正无缝的一整块（那条"缝"只出现在"墙 ↔ 非墙"交界，是正确的轮廓）。

### 明度阶梯（关键）

```
外域 0.02  <  地板 0.12–0.15  <  墙 0.24–0.31  <  道具 0.35–0.78  <  玩家 0.85
```

只有「墙 / 地板」这一对必须拉开 **≥2× 亮度比**，其余靠色相区分。实测四时刻稳定在 **2.07–2.12×**
（`tools/crop.gd` 的 `[sample]` 行可直接读到）：

| 时刻 | 地板 lum | 墙 lum | 比值 |
|---|---|---|---|
| Ⅰ 铸造·晨 | 0.138 | 0.286 | **2.07×** |
| Ⅱ 新光·昼 | 0.146 | 0.309 | **2.12×** |
| Ⅲ 锈时·昏 | 0.114 | 0.242 | **2.12×** |
| Ⅳ 沉寂·夜 | 0.124 | 0.260 | **2.10×** |

> 地板在三处不同格子（西厅 (2,1) / 西厅 (5,4) / 东厅 (9,5)）取样**完全同色**（如 T1 均为 `#232625`）——
> 这正是"地板是一整片"的量化证据。

### 绘制顺序（`EnvironmentLayer._draw()`）

```
房间外(上下两条带) → 地板(整片单色) → 墙根 AO → 墙投影 → 墙体(逐格同色不描边) → 交界斜面 → 外轮廓 → 粒子
```

道具 / 目标格光晕 / 玩家由 `LevelManager` 的 `Entities`、`GoalMarker`、`Player` 节点在上层绘制。
**`GoalMarker` 必须在道具之上** —— 画在道具下层会被出口门整格盖住（v2 踩过这个坑）。

### 其它元素

| 元素 | 做法 |
|---|---|
| 目标格 | 黄铜四角折线，画在 `GoalMarker` 层 |
| 玩家 | 暖色柔光晕 → 接地影 → 亮米色本体 + 近黑粗描边 → 黄铜轴心；面向格用**四角折线标** |
| 时刻分区 | 罗马刻度 + 光向（墙斜面 / 墙投影）+ 粒子 SPARK·DUST·RUST·ASH + 亮度 + 色温（后两者由乘法调色承担） |

### HUD 仪表台（本轮 UI 优化）

诊断（看图 + 量像素，不靠猜）：**三组常驻信息 + 三个按钮各自浮在一片近黑底上**，
彼此没有关联、上下没有分界 —— 读起来是"调试浮层"而不是"仪表面板"。四条具体问题：

| # | 问题 | 证据 / 根因 |
|---|---|---|
| ① | **没有背板、没有分界** | HUD 区其实是世界 `C_VOID`（`#05070B`）被时刻色调染过的一片，底部没有任何东西把"仪表"与"场景"切开 → 世界顶端像被硬压了一条黑边 |
| ② | **按钮是 Godot 默认主题** | 圆角灰玻璃，而场景里所有东西都是程序化绘制的**方角黄铜**，两套语言，一眼出戏 |
| ③ | **状态行重复信息** | `tc.status_text()` 把「时刻 / 时砂 / 背包」又抄了一遍，真正独有的「坐标 / 面向」被淹没 |
| ④ | **刻度名铭牌是空框** | `time_ruler.gd` 在刻度下画了铭牌底色，却从没写 `tp.label` —— 4 个空荡荡的深色矩形 |
| ⑤ | **游标压住当前罗马刻度** | 游标原是 10px 宽的浅色长条（y 8..70），正好盖在当前刻度的数字上 —— 最该被看见的色盲安全主标识被自己的游标挡住 |

改法（新增 `src/ui/ui_style.gd` 作为**唯一调色板**，调色板原先以字面量散落在 5 个文件里）：

```
HUD（CanvasLayer）
├─ Band     自绘背板 #0E1216@0.94 + 黄铜分界线(y=138) + 世界侧三级软阴影(y=140..152)
├─ TimeRuler   面板(16,16,440,108)  铭文「时刻」＋ 真字形 Ⅰ–Ⅳ ＋ 断裂刻度 ＋ 时刻名铭牌
├─ Hourglass   面板(468,16,148,108) [沙漏图标] [铭文 时砂 / 12 / 12]，耗尽时边框转警告色
├─ Backpack    面板(628,16,168,108) 铭文「背包 x/2」＋ 2 槽 ＋ 程序化六芒「冻结」徽章
├─ 按钮 ×3     方角黄铜四态样式 + 热键角标（Z/R/H 独立配色，不再糊成 "撤销Z"）
└─ 状态行      只留独有信息「坐标 (x,y) ｜ 面向：…」，弱化配色、右对齐到按钮右边界
```

另外补上 **GDD §7「死锁时撤销按钮高亮呼吸」** —— 这条原先只写在设计文档里、实现里没有：
`deadlock_detected` 触发后按钮边框在 4 s 内呼吸一次再收回常态黄铜（只做注意力提示，不改任何游戏状态）。

> ⚠ **`BAND_H = 140` 同时是世界网格原点**，HUD 与关卡坐标都挂在这个数上 —— 只能改 HUD 内部版式，不能改这个数。
> 回归用例 `tests/test_hud_layout.gd` 把这条连同"面板互不重叠 / 不越界 / 铭牌可点 / 状态行不重复"一起锁死了。

### 顺带修掉的三处遮挡

- **提示条**从 y=500 下移到**贴住画布底边**（`src/ui/hint_layer.gd`）：原位置压住第 3 行下半部分，
  把压力板遮掉一角；现在内容少时只覆盖最下面那行（y=7，全是边界墙），**不遮挡任何可通行格**。
  宽度 1216px（画布 1248 − 左右各 16），让常驻指令句**一行放下**（原先在 880px 里会被折成两行）。
- **提示条改为"底边锚定 + 向上生长"**：早先的实现把**顶边钉死在 y=812 往下长**、高度按
  `22 × 行数 + 12` 硬算 → 连按 `H`（4 行）或按一次 `Tab`（5 行）就会顶出 908 的画布底边，
  最后几行被边框切掉（实测第 4 行文字正好被切在设计 y=904..908 上，提示条自己的下边框整条跑到画外）；
  硬算高度也追不上真实字体行高与自动折行，边框会压到字上。
  现在**底 / 边框 / 内边距全部交给 `StyleBoxFlat`，高度由 `PanelContainer` 按文本真实高度撑开**，
  整条贴住画布底边并**向上生长**（距底留 8px）→ 行数再多也只是往上长，且边框永远在文字之外。
  回归用例：`tests/test_hint_layout.gd`。
- **HUD 的全屏色调叠加层已删除**（`hud.gd` 的 `_tint`）：世界层已用乘法调色承担该通道，
  再叠一层 0.16 的加色叠加会把暗部整体抬亮、压低对比 —— 正是可读性的敌人。
